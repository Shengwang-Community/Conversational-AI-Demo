# Applying lessons

Use the current request, code, checks and any useful notes as evidence. A retrospective can happen when helpful; it does not depend on a role handoff or task-state schema.

Keep the lesson concrete: what failed, why, where the correction applies and how it was verified. Update relevant docs or skills within the user's authorized scope. Otherwise, describe the proposed improvement for follow-up.

Optional local memory lives under this skill's `memory/`. Preserve existing records; publishing and Git actions follow the user's authorization.
